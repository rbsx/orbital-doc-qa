# Orbital — Product Engineering Take-Home

**Loom walkthrough:** _link to be added_

A document Q&A tool for commercial real estate lawyers, extended so they can **trust an answer and check it in one click**, **work across a whole deal's documents**, and **see where those documents disagree**.

## What I built

- **Verifiable citations.** Every claim in an answer carries an exact quote from the document, and the server checks that the quote really is on the cited page. Clicking the chip (`Report on title 100… · p.3`) opens that page with the quote highlighted. Anything that doesn't check out is flagged amber: "check before relying on it".
- **Multi-document deals.** Put the lease, report on title and survey for a deal into one conversation. A **Deal documents** panel lets you open, add or remove them, and answers draw on all of them.
- **Conflict check.** With two or more documents, the app flags where they disagree (the landlord isn't the registered owner, the permitted use breaks a covenant, the lease area isn't what the survey measured). Each conflict comes with verified sources on both sides and an **Ask to explain** button.

Plus a pass over the rough edges a lawyer would hit first:
- **Fixes:** times that were an hour off, replies leaking between chats, silent upload failures, scans reported as "no document", password-protected PDFs.
- **Additions:** suggested first questions, accessibility and a cleaner new-chat flow.

**Why these, what I'd do next, and how I worked with AI (including parallel subagents): [DECISIONS.md](DECISIONS.md).**
Everything landed as small PRs ([#1](https://github.com/rbsx/orbital-doc-qa/pull/1)–[#12](https://github.com/rbsx/orbital-doc-qa/pull/12)); full diff from the starting code: [`851ccdd...main`](https://github.com/rbsx/orbital-doc-qa/compare/851ccdd...main).

## Try it in 60 seconds

1. Start the app (see [Setup](#setup)) and open http://localhost:5173.
2. Upload the three PDFs in `sample-docs/deal-100-bishopsgate/`. They're one deal, with three planted conflicts ([details](sample-docs/deal-100-bishopsgate/README.md)).
3. Within about 15 seconds, **"3 possible conflicts across documents"** appears above the chat. Open it and click a source chip: the PDF jumps to the page and highlights the quote.
4. Click a suggested question, or ask your own, e.g. *"Who is the landlord, and are they the registered owner?"* Hover a citation chip to see the exact quote, and click it to open the source.

## Setup

### Prerequisites
- Docker and Docker Compose
- just (command runner) — install via `brew install just` or `cargo install just`

That's it. Everything else runs inside containers.

### Getting Started

1. Clone this repository

2. Run the setup command:
```
just setup
```
   This copies `.env.example` to `.env` and builds the Docker images.

3. Add your Anthropic API key to `.env`:
```
ANTHROPIC_API_KEY=your_key_here
```

4. Start everything:
```
just dev
```
   This starts PostgreSQL, the FastAPI backend (port 8000), and the React frontend (port 5173), all bound to `127.0.0.1`.
   Database migrations run automatically when the backend starts — no separate step needed.

5. Open http://localhost:5173 in your browser.

Your local `backend/src/` and `frontend/src/` directories are mounted into the containers —
edit files normally on your machine and changes hot-reload automatically.

### Sample Documents

- `sample-docs/deal-100-bishopsgate/`: a lease, report on title and measured survey for one building, with planted conflicts (generated by `scripts/generate-deal-pack.py`)
- `sample-docs/*.pdf`: the original single-document samples

### Project Structure

- `frontend/` — React frontend (Vite + Tailwind + shadcn/Radix UI)
- `backend/` — FastAPI backend (Python 3.12 + SQLAlchemy + PydanticAI)
  - `services/document_context.py`: document labels, prompt context and quote matching, shared by chat, citations and the conflict check
  - `services/citations.py` and `services/conflicts.py`: citation checking and the conflict analysis
- `alembic/` — Database migrations
- `docs/CONTRACT.md` — the contract the parallel feature branches were built against
- `sample-docs/` — Sample PDF documents for testing

### Useful Commands

- `just dev` — Start full stack (Postgres + backend + frontend)
- `just stop` — Stop all services
- `just reset` — Stop everything and clear database
- `just check` — Run all linters and type checks
- `just fmt` — Format all code
- `just db-init` — Run database migrations
- `just db-shell` — Open a psql shell
- `just shell-backend` — Shell into backend container
- `just logs-backend` — Tail backend logs
